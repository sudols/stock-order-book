Q11 — Design Documents

(933 chars — within 500–1000)

The overall architecture follows a client-server model with three distinct layers. The frontend React app communicates with the backend via two channels: tRPC for mutations/queries (like placing orders and fetching portfolio) and Socket.io for real-time order book push events. The backend is split into three core modules — the OrderBook (pure data structure with HashMaps and sorted arrays), the MatchingEngine (price-time priority logic), and the PortfolioManager (user balance tracking). Firebase handles authentication, and the ID token is verified on every API call. The shared package keeps TypeScript types in sync between client and server so there's no type drift. Use-case wise, the main flow is: user logs in → places order → matching engine checks for a match → if matched, trade executes and portfolios update → order book event is broadcast to all clients. If not matched, the order rests on the book as a maker order.
